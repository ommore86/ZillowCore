# EstateOS AI / ZillowCore — System Architecture Document

## 1. Executive Topology

EstateOS AI (ZillowCore) is architected as an autonomous multi-tenant enterprise real estate operating system combining:
1. **Deterministic Geo-Spatial Data Fabric (ZillowCore Engine):** High-concurrency PostGIS geo-spatial indexing, 1536-dimensional interior visual vector search, continuous multimodal property valuation (MVE / Autonomous Zestimate), and self-healing RESO/MLS data ingestion micro-sandboxes.
2. **Enterprise Domain Core (EstateOS SaaS):** Relational property lifecycle management, 14-role RBAC multi-tenancy, double-entry financial accounting (INR/GST), CRM with 6-stage Kanban lead progression, digital lease contracts with e-signatures, and maintenance dispatch.
3. **Multi-Agent Orchestrator (LangGraph Multi-Agent Architecture):** Centralized Master Orchestrator coordinating 24 specialized domain agents with execution logs and human-in-the-loop approval gates.

## 2. ZillowCore High-Scale Data Core & Valuation Engines

### 2.1 Module A: Neural Geo-Spatial Query Router (NGQR)
Supersedes legacy SQL relational queries generated by client-side dropdown maps. It parses natural language spatial queries (e.g. *"Find a home in northeast Bhopal near reputed schools under ₹2,00,00,000"*) directly into PostGIS bounding-box polygon filters, semantic visual vectors, and strict price ceilings. It produces sub-50ms execution resolutions through geohash caching.

### 2.2 Module B: Multimodal Valuation Engine (MVE — The Autonomous Zestimate)
Processes non-linear asset valuation at scale:
- Extracts interior computer vision texture cues (Italian marble, stone countertops, distressed hardwood, natural lighting ratios).
- Synthesizes structural attributes (beds, baths, square footage, building age).
- Ingests macroeconomic benchmarks and satellite neighborhood infrastructure scoring.
- Outputs continuous valuation amount with an **Active Confidence Matrix** (Upper & Lower bounds, variance percentage, and analytical breakdown).

### 2.3 Section 5: Autonomous RESO / Data Ingestion Sandbox
Self-healing upstream MLS feed connector:
- Anomaly Detector: flags upstream schema permutations and missing standard RESO fields.
- Micro-VM Sandbox: auto-synthesizes Rust WebAssembly parsing adapters.
- Mock Cache Verification: stream-tests compiled binary against historical cache for 100% extraction match prior to live deployment.

## 3. Multi-Tenant Isolation Model

Tenant isolation is enforced strictly at the database and API query levels. Every database table contains `org_id UUID NOT NULL` indexed foreign key to `organizations`. All FastAPI route handlers depend on `get_current_user`, which binds the caller's JWT token or API key to an organization identifier. All SQL queries filter explicitly on `org_id == current_user.org_id`, mathematically preventing data leakage across competitor organizations.
